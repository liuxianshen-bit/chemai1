## Context

当前 ChemAI 前端有两个页面职责边界模糊：

- **teacher.html（学情面板）**：包含班级级聚合图表（知识点错误率、障碍分布、成绩趋势），但也包含个体学生列表表格和学生详情弹窗——这些是个体学生管理功能，不应放在聚合分析页面。
- **students.html（学生管理）**：只有搜索框+班级筛选+纯文字行列表，缺少学生管理应有的卡片视图、详情面板、添加/导入功能。

对标 Google Classroom People 页面和 Canvas LMS 的 Context Card 模式，行业标准采用「班级宏观 / 个体微观」双层架构：学情面板是俯瞰全班数据的鸟瞰图，学生管理是个体学生信息的操作中心。

纯 HTML/CSS/JS 前端，无框架。后端 API 不变。

## Goals / Non-Goals

**Goals:**
- students.html：从纯文字列表升级为卡片网格+详情 Drawer+添加学生弹窗的完整学生管理页面
- teacher.html：删除个体学生列表和详情弹窗，回归纯班级聚合分析视角，新增「重点关注学生」精选卡片横条
- 视觉风格与现有 6 个页面保持一致（暖调实验室笔记本）

**Non-Goals:**
- 不新增后端 API
- 不引入新 CDN 依赖
- 不改动学生管理的 JS 文件架构（继续用 `students.js` 承载新增逻辑）
- 不碰考试工作台、OCR、障碍诊断、登录等其他页面

## Decisions

### D1: 学生列表 → 卡片网格
**选择**: CSS Grid（`grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))`）
**理由**: 卡片比表格更适合展示学生个体信息（头像+多维标签+操作入口），行业标准也以卡片为主。240px 最小宽度保证每行至少 3 张卡片（在 800px+ 内容区）。
**备选**: 保留表格但增加列 → 放弃，表格适合密集数据对比，不适合"每个学生是一个独立对象"的管理场景。

### D2: 详情面板 → 右侧 Drawer
**选择**: 固定 480px 宽右侧滑出面板，overlay + backdrop
**理由**: Canvas Context Card 和 Google Classroom 都用浮层而非跳页。Drawer 保持页面上下文不丢失，用户看完详情可直接回列表。480px 够展示 KPI 卡片+迷你图表+知识点标签。
**备选**: Modal 居中弹窗 → 放弃，Modal 打断上下文，且移动端适配不如 Drawer。

### D3: 学情面板的「重点关注学生」→ 水平横条
**选择**: 水平滚动的卡片横条（3-5 张卡片），每张只显示头像+姓名+障碍类型，点击跳转到 students.html 并自动定位
**理由**: 学情面板的核心是鸟瞰，不应放完整列表。5 张以内的碎片信息给老师一个"快速感知"，深入了解走学生管理页面。
**备选**: 完全删除学生相关 → 过于激进，老师需要从学情快速定位到个体学生。

### D4: 图表 → 复用 Chart.js
**选择**: 详情 Drawer 内的成绩趋势使用 Chart.js 迷你折线图（与学情面板一致）
**理由**: 已在项目中，无需新依赖。配置精简版（隐藏坐标轴标签、缩小尺寸到 160px 高）。

### D5: Mock 数据保持一致
**选择**: teacher.html 的重点关注学生 Mock 数据与 students.html 共享同源
**理由**: 避免两处 mock 数据不同步，students.html 的 mockStudentsData() 可以直接复用。

## Risks / Trade-offs

- **卡片网格在移动端可能过窄** → 在 < 600px 时切换为单列布局（`minmax(240px, 1fr)` 自然处理）
- **Drawer 在移动端 480px 可能溢出** → 在 < 600px 时 Drawer 宽度改为 100vw
- **Chart.js 在 Drawer 内重复初始化** → 每次打开 Drawer 时 destroy 旧实例再创建新实例
- **students.js 文件可能过大** → 当前 students.js 约 200 行，新增卡片渲染+Drawer 逻辑后约 400 行，仍在单文件可维护范围内
